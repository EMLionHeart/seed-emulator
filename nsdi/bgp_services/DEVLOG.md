# BGP Services Devlog

## Core Promotion Files

### `seedemu/services/BgpServiceCommon.py`

Shared internal support for promoted BGP backend services.

Responsibilities:

- router resolution
- endpoint metadata
- exposure handling
- common file helpers
- common BIRD patch helpers
- shared control/observation path constants

### `seedemu/services/BgpControlService.py`

Core router-local BGP control service.

Responsibilities:

- router-first control attachment
- control wrapper patch injection
- dynamic policy/state file setup
- runtime control process installation
- control endpoint metadata export

Runtime control modifies router-local policy/state files through the helper process and applies changes with `birdc configure`.
It does not modify the main `bird.conf` at runtime.

### `seedemu/services/BgpObservationService.py`

Core router-local BGP observation service.

Responsibilities:

- router-first observation attachment
- birdwatcher installation and startup wiring
- observation-specific BIRD patching
- observation endpoint metadata export

Observation data comes from the local BIRD control socket and is exposed through birdwatcher.

### `seedemu/services/__init__.py`

Exports promoted services from the public `seedemu.services` package.

Current change:

- adds `BGPControlService`
- adds `BGPObservationService`

## Service Usage Entry Points

Import:

```python
from seedemu.services import BGPControlService, BGPObservationService
```

Use:

- instantiate the service object
- call `attachRouter(...)` for control
- call `observeRouter(...)` for observation

Constraints:

- do not use `emu.addLayer()`
- `_createServer()` is intentionally disabled to prevent vnode-install style misuse

## Relationship Between `nsdi/bgp_services/` And `seedemu/services/`

`nsdi/bgp_services/` is the staging and design-freeze workspace.

`seedemu/services/` is the promoted core home for the stable backend abstractions.

Current practical split:

- `nsdi/bgp_services/`
  - design notes
  - local smoke test
  - frozen structure reference
- `seedemu/services/`
  - promoted reusable backend implementation
  - public import surface for future examples

## Current Design Constraints

### Control Three-Layer Model

- base `bird.conf` is generated by SEED
- render only injects include/wrapper structure
- runtime only rewrites control policy/state files
- runtime applies changes through `birdc configure`

### Router-First Attachment

- router-first is the only primary attachment model
- direct `Router` attachment is the main path
- `as_obj` plus `router_name` is kept only as a compatibility entry point

### Exposure Mode

Supported modes:

- `local`
- `internal`
- `host`

Control uses exposure as public API and metadata.

Observation currently records stable internal endpoint metadata.

### Wrapper Semantics

- wrapper preserves original SEED eBGP filter intent
- control only adds outer guard logic around preserved import/export behavior
- runtime does not rewrite protocol blocks in `bird.conf`

## Explicitly Unsupported Scope

- iBGP control
- Alice service
- compiler extension
- generalized BIRD patching beyond SEED's current eBGP inline filter structure
