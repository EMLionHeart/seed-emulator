# BGP Services Abstraction

`nsdi/bgp_services/` is the current staging area for reusable BGP control and observation logic extracted from the B30 example.

This directory is intentionally limited in scope:

- it defines the current abstraction shape for control and observation
- it does not change `seedemu/services/`
- it does not change `seedemu/compiler`
- it does not make Alice-LG generic
- it does not replace the B30 example's external Alice glue

## Scope

The current phase only formalizes the reusable backend pieces:

- `BGPControlService`
- `BGPObservationService`
- internal helpers for router resolution, endpoint metadata, BIRD config patching, and exposure handling

Alice-LG remains outside this abstraction:

- B30 may keep its example-specific compose/config glue
- `BGPObservationService` does not generate Alice config
- no Alice service is defined here

## Common Design Rules

### Router-First Attachment

Both services attach to explicit routers.

Supported forms:

- pass a `Router` directly
- pass `as_obj` plus `router_name`

Semantic rule:

- router-first is the only primary attachment model
- `as_obj` is kept only as a compatibility entry point
- no new semantics should be added around `as_obj`

Not allowed:

- inferring a default router for an AS

This rule is enforced by `resolve_router(...)` in [helpers.py](/home/seed/seed-emulator/nsdi/bgp_services/helpers.py:106).

### Stable Endpoint Metadata

Services report endpoint metadata through a common helper:

- router identity: `asn`, `router`
- transport identity: `node_port`, `protocol`
- exposure identity: `exposure_mode`, `bind_host`, `host_port`
- endpoint views:
  - `endpoint`: canonical endpoint for the selected exposure mode
  - `endpoints.local`
  - `endpoints.internal`
  - `endpoints.host`

This is built by `build_endpoint_metadata(...)` in [helpers.py](/home/seed/seed-emulator/nsdi/bgp_services/helpers.py:128).

### BIRD Patching

All BIRD config mutations go through helper-level patch functions:

- `ensure_bird_include(...)`
- `patch_bird_config(...)`

The intent is to keep service code focused on what is being injected, not on ad hoc file rewrite mechanics.

## Exposure Handling

Exposure handling is defined centrally in [helpers.py](/home/seed/seed-emulator/nsdi/bgp_services/helpers.py:24).

Supported modes:

- `local`
  - service binds `127.0.0.1`
  - no host port mapping
- `internal`
  - service binds `0.0.0.0`
  - reachable from the emulation via router address/loopback
  - no host port mapping
- `host`
  - service binds `0.0.0.0`
  - `Node.addPortForwarding(...)` maps container port to host port
  - if `host_port` is omitted, it defaults to the node port

Current service usage:

- `BGPControlService` exposes this as public API
- `BGPObservationService` currently records stable internal metadata only

## BGPControlService

Implementation: [control.py](/home/seed/seed-emulator/nsdi/bgp_services/control.py:1)

### Responsibility

`BGPControlService` installs a router-local HTTP control endpoint that manages dynamic BGP policy state without performing runtime edits to the SEED-rendered base config.

### Three-Layer Model

This service must preserve the following model:

1. Static base layer
   - `/etc/bird/bird.conf`
   - generated by SEED
   - never modified at runtime

2. Render-time wrapper layer
   - render injects include/wrapper logic into the static config
   - wrapper keeps the original SEED import/export intent in `bird.conf`
   - control only adds outer guard logic before or around that preserved intent
   - runtime policy enters only through helper functions referenced by the wrapper, not by rewriting protocol blocks
   - current wrapper patching is explicitly scoped to SEED's existing eBGP-generated inline BIRD filter structure
   - this phase does not aim to support arbitrary BIRD configuration shapes
   - if broader support is needed later, it should come from an explicit rendering extension point rather than broadening runtime rewrites

3. Runtime dynamic layer
   - `/etc/bird/bgp_control.conf`
   - `/etc/bird/bgp_control_state.json`
   - runtime only rewrites these dynamic files
   - changes are applied through `birdc configure`

The service records this file layout on the router via `bgp_control_layout`.

### Public Attachment Shape

Primary attachment API:

```python
control = BGPControlService()
control.attachRouter(router)
control.attachRouter(as150, "r1", exposure_mode="host", host_port=18081)
```

Batch shape:

```python
control.attachRouters([
    {"router": router_a},
    {"as_obj": as150, "router_name": "r1", "exposure_mode": "internal"},
])
```

### Current Control Endpoints

- `GET /healthz`
- `GET /state`
- `POST /policy/enable`
- `POST /policy/disable`
- `POST /policy/export/allow`
- `POST /policy/export/deny`
- `POST /policy/import/reject`
- `POST /policy/reload`

## BGPObservationService

Implementation: [observation.py](/home/seed/seed-emulator/nsdi/bgp_services/observation.py:1)

### Responsibility

`BGPObservationService` installs birdwatcher on selected routers, patches the rendered BIRD config with observation-specific requirements, and records stable observation endpoint metadata.

### Current Shape

- router-local birdwatcher process
- router-first attachment
- stable endpoint metadata via the shared helper
- router state file with endpoint and runtime binary/config paths

Primary attachment API:

```python
observation = BGPObservationService()
observation.observeRouter(router)
observation.observeRouter(as2, "r100")
```

Batch shape:

```python
observation.observeRouters([
    {"router": router_a},
    {"as_obj": as2, "router_name": "r100"},
])
```

### Non-Goals For This Phase

- no Alice-LG config export
- no Alice-LG container attach helper
- no generic looking glass frontend abstraction

## Relation To B30

The B30 example remains the integration example for this work, but it is not the home of the reusable backend abstraction.

Current division of responsibility:

- `nsdi/bgp_services/`
  - reusable control/observation backend logic
- `examples/internet/B30_bgp_services/`
  - topology
  - mode selection
  - example-only Alice-LG glue

## Non-Goals

The following are explicitly out of scope for this phase:

- moving these classes into `seedemu/services/`
- adding compiler support in `seedemu/compiler/`
- generalizing Alice-LG
- redesigning B30
- introducing a monolithic combined BGP framework object
